# antizapret-go

Проект вдохновлён [GubernievS/AntiZapret-VPN](https://github.com/GubernievS/AntiZapret-VPN)
и не претендует на авторство идеи или применённых в нём решений. Цель —
минимизация зависимостей и простота развёртывания новых инсталляций при
сохранении достаточной гибкости. Поднятие VPN, firewall и маршрутизация остаются
на стороне оператора; antizapret-go отвечает только за проксирование (подмену DNS).

DNS-прокси для **селективной маршрутизации по доменам**: через VPN-туннель
направляется трафик только к доменам из заданных списков, остальное идёт напрямую
(split-tunnel по доменам, а не по IP).

Сервис работает как DNS-резолвер для клиента: резолвит имя, классифицирует домен
по спискам и для доменов из remap-списка отдаёт клиенту **fake-IP** из приватного
пула вместо реального адреса, попутно программируя nftables DNAT `fake → real`.
Пул fake-IP целиком заворачивается в туннель маршрутизацией, поэтому в туннель
попадает только нужный трафик.

## Как это работает

```
DNS-запрос клиента
      │
      ▼
   [ cache ] ──hit──► ответ (с пересчётом TTL)
      │ miss
      ▼
 [ resolver ] ── round-robin апстримы с фолбэком ──► кэшируем ответ
      │
      ▼
 [ router ] ── классификация домена по radix (longest-prefix по реверс-домену)
      │
      ├─ passthrough → реальный IP как есть (трафик напрямую)
      ├─ blackhole   → A заменяется на 127.6.6.6 (домен отбрасывается, sinkhole)
      └─ remap       → A заменяется на fake-IP из fake_cidr,
                       в nftables прописывается map fake → real (DNAT)
```

1. Клиент использует сервис как DNS-резолвер.
2. Кэш (ключ = `имя|тип|класс`); на miss — резолвинг через апстримы (round-robin
   со стартовым смещением и фолбэком на следующий при сбое).
3. Роутер определяет действие для **запрошенного** домена.
4. Для `remap` берётся fake-IP из пула, программируется DNAT в prerouting; клиент
   получает fake-IP, коннект к нему заворачивается в туннель и на этой машине
   разворачивается обратно в реальный адрес.
5. `AAAA` для `remap`/`blackhole` вырезается — чтобы реальный IPv6 не утёк мимо
   туннеля; клиент падает на IPv4.
6. Маппинги fake→real живут ограниченное время (`firewall.ttl`) и переиспользуются;
   списки перечитываются периодически и по `SIGHUP`; снимки списков персистятся
   в bbolt — для быстрого старта и устойчивости к временной недоступности
   источников (last-known-good).

## Требования

- **Linux** — сервис использует nftables, на других ОС не собирается/не работает.
- Права на управление nftables (`CAP_NET_ADMIN`, обычно — запуск от root).
- Внешняя настройка (вне этого сервиса): маршрутизация `fake_cidr` в туннель,
  `net.ipv4.ip_forward=1`, при необходимости SNAT/masquerade на исходящем
  интерфейсе. Сам сервис программирует только DNAT-набор в nftables.

## Сборка

`make` собирает бинарь в `build/antizapret_go` (`GOOS=linux`, `CGO_ENABLED=0`,
арка хоста; версия проставляется через ldflags):

```sh
make
```

Под другую архитектуру — напрямую через `go build`:

```sh
GOOS=linux GOARCH=amd64 go build -o antizapret_go ./cmd/
```

## Запуск

```sh
# показать дефолтный конфиг
./antizapret_go -default-config > config.yaml

# запуск с конфигом (нужны права на nftables)
sudo ./antizapret_go -config config.yaml
```

Флаги: `-config <path>` — путь к конфигу; `-default-config` — напечатать дефолтный
конфиг и выйти; `-help` — справка. Без `-config` используется встроенный дефолт.

## Конфигурация

### `bindings` — слушатели DNS

| Поле       | Описание                                  |
|------------|-------------------------------------------|
| `address`  | адрес прослушивания (`127.0.0.1`, …)      |
| `port`     | порт (обычно `53`)                        |
| `protocol` | `udp` или `tcp`                           |

Bind на wildcard (`0.0.0.0`/`::`) логируется предупреждением — следите, чтобы не
получился open-resolver.

### `upstreams` — вышестоящие DNS

| Поле      | Описание                                                                 |
|-----------|--------------------------------------------------------------------------|
| `name`    | имя (для логов; по умолчанию — хост)                                      |
| `dsn`     | `udp://host:53`, `tcp://host:53` или `https://host/dns-query` (DoH)       |
| `timeout` | таймаут одной попытки к этому апстриму                                    |

Апстримы перебираются по кругу с фолбэком; общий бюджет запроса — `request_timeout`.

### `policy` — списки и их перезагрузка

- `reload_interval` — период автоматического ребилда роутера (также по `SIGHUP`).
- `matchers` — источники списков (см. ниже).

### `policy.matchers[]` — источник списка

| Поле         | Описание                                                                            |
|--------------|-------------------------------------------------------------------------------------|
| `name`       | имя источника (ключ кэша снимков)                                                    |
| `type`       | `remap` / `blackhole` / `passthrough`                                                |
| `source`     | `file:///path` или `http(s)://…`                                                     |
| `format`     | `plain` (домен на строку, `#`-комментарии) или `regexp` (escape-hatch)               |
| `subdomains` | `true` ⇒ домен и поддомены (`*.domain`), `false` ⇒ только точное совпадение; деф. `true` |
| `prune`      | `true` ⇒ записи источника обрезают все более специфичные ветки под собой (см. ниже) |
| `regexp`     | для `format: regexp` — `{ from, to }`: строки, матчащие `from`, преобразуются в `to` |
| `filter`     | `{ exclude: [regexp, …] }` — отбросить записи, чьи (канонические) домены матчат любой |

**Разрешение совпадений.** Действие домена определяет **самая специфичная** запись
(longest-prefix): `www.example.com` из одного источника победит `example.com` из
другого независимо от их порядка. Порядок (last-wins) важен только для **полностью
совпадающего** ключа.

**`prune`** даёт оператору вайлдкард-оверрайд поверх чужих списков. Запись prune-источника
обрезает все более специфичные ветки под своим префиксом на момент обработки: если
community-лист добавил `www.example.com remap`, а ваш prune-`passthrough` источник —
`example.com`, то весь `*.example.com` пойдёт напрямую, перекрыв специфичную запись.
Так как прунинг точечный во времени, prune-источник должен идти **после**
перекрываемых списков (обычно — в конце). Это per-source флаг: чтобы в одном наборе
смешать вайлдкард-оверрайды и специфичные исключения, разнесите их по нескольким
упорядоченным источникам.

### Прочее

| Поле               | Описание                                                                      |
|--------------------|-------------------------------------------------------------------------------|
| `fake_cidr`        | пул fake-IP для `remap` (напр. `10.30.0.0/15`); должен заворачиваться в туннель |
| `cache.capacity`   | максимум записей в DNS-кэше                                                    |
| `cache.ttl`        | дефолтный TTL кэша, если у ответа нет своего                                   |
| `firewall.backend` | `nft` (по умолчанию) или `iptables` — чем программировать DNAT (см. ниже)      |
| `firewall.set`     | имя nftables-set (только для `nft`)                                            |
| `firewall.chain`   | имя цепочки DNAT (NAT/prerouting) — для обоих бэкендов                         |
| `firewall.ttl`     | время жизни маппинга fake→real (после чего IP переиспользуется)                |
| `request_timeout`  | общий бюджет на резолвинг одного запроса (покрывает фолбэк по апстримам)       |
| `logging_severity` | `debug` / `info` / `warn` / `error`                                            |
| `state_path`       | путь к bbolt-файлу (persistent кэш списков + быстрый старт)                    |

### Бэкенды DNAT (`firewall.backend`)

- **`nft`** (по умолчанию) — nftables через netlink; маппинг `fake→real` хранится
  в set-map (хеш-поиск), домен пишется в комментарий элемента.
- **`iptables`** — для хостов без доступа к nftables-netlink, legacy-систем и
  совместимости с инсталляциями оригинала. Маппинг — линейная цепочка DNAT-правил
  (по правилу на адрес): на больших объёмах матчинг медленнее nft-хеша. Правила
  без комментария-домена (iptables `-D` матчит правило целиком), поэтому будущее
  восстановление кэша из правил возможно только для `nft`. Требует таблицу `nat`
  и прав на iptables.

## Известные ограничения

- **Только IPv4.** `remap`/`blackhole` работают по IPv4: для таких доменов `AAAA`
  вырезается из ответа, клиент использует IPv4. Домен, доступный только по IPv6,
  работать через прокси не будет.
- **Исчерпание пула.** Если свободные адреса `fake_cidr` закончились, новые
  remap-домены получают `SERVFAIL`, пока адреса не высвободятся по `firewall.ttl`.
  Запас регулируется размером `fake_cidr`.
- **Наблюдаемость.** Нет метрик и health/ready-эндпоинта — мониторинг только по
  логам.
- **Обновление списков.** Источники тянутся последовательно (много источников ⇒
  дольше старт/перезагрузка); нет conditional GET (ETag) — каждый refresh качает
  список целиком; строка длиннее 64 КБ в источнике ломает его парсинг.
- **Пиковая нагрузка.** Кэш маппингов (`SafeTTLMap`) использует глобальные локи;
  при экстремальном qps возможна деградация на контеншене (не профилировалось).
- **Рестарт сбрасывает состояние.** При перезапуске nft-set флашится, а DNS-кэш
  и `fake→real` маппинги теряются: активные коннекты к fake-IP рвутся до повторного
  разрешения домена. Планируется восстанавливать и маппинги, и DNS-записи кэша из
  nft (домен хранится в комментарии элемента), без потери непрерывности.
- **Память radix без прунинга.** Дерево не схлопывает избыточные поддомены: если в
  списке есть и `example.com` (с поддоменами), и `www.example.com`, второй держится
  отдельным узлом, хотя `MatchPrefix` его и так покрывает (на корректность не влияет).
  Полный набор из референса (~1.6 млн уникальных доменов) занимает ~210 MB; прунинг
  срезал бы ~18%. Для VPS терпимо; на маленьких хостах стоит сократить списки. Дубли
  пересекающихся источников radix схлопывает сам, так что память от них не растёт.
