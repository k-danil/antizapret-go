# antizapret-go

DNS-прокси для **селективного обхода блокировок**: через VPN-туннель направляется
трафик только к доменам из списков, остальное идёт напрямую (split-tunnel по
доменам, а не по IP).

Сервис работает как DNS-резолвер для клиента: резолвит имя, классифицирует домен
по спискам и для заблокированных доменов отдаёт клиенту **fake-IP** из приватного
пула вместо реального адреса, попутно программируя nftables DNAT `fake → real`.
Пул fake-IP целиком заворачивается в туннель маршрутизацией, поэтому в туннель
попадает только нужный трафик.

## Как это работает

```
DNS-запрос клиента
      │
      ▼
   [ cache ] ──hit──► ответ (с пересчётом TTL)
      │ miss
      ▼
 [ resolver ] ── round-robin апстримы с фолбэком ──► кэшируем ответ
      │
      ▼
 [ router ] ── классификация домена по radix (longest-prefix по реверс-домену)
      │
      ├─ passthrough → реальный IP как есть (трафик напрямую)
      ├─ blackhole   → A заменяется на 127.6.6.6 (домен заблокирован)
      └─ remap       → A заменяется на fake-IP из fake_cidr,
                       в nftables прописывается map fake → real (DNAT)
```

1. Клиент использует сервис как DNS-резолвер.
2. Кэш (ключ = `имя|тип|класс`); на miss — резолвинг через апстримы (round-robin
   со стартовым смещением и фолбэком на следующий при сбое).
3. Роутер определяет действие для **запрошенного** домена.
4. Для `remap` берётся fake-IP из пула, программируется DNAT в prerouting; клиент
   получает fake-IP, коннект к нему заворачивается в туннель и на этой машине
   разворачивается обратно в реальный адрес.
5. `AAAA` для `remap`/`blackhole` вырезается — чтобы реальный IPv6 не утёк мимо
   туннеля; клиент падает на IPv4.
6. Маппинги fake→real живут ограниченное время (`nft.ttl`) и переиспользуются;
   списки перечитываются периодически и по `SIGHUP`; снимки списков персистятся
   в bbolt — для быстрого старта и устойчивости к временной недоступности
   источников (last-known-good).

## Требования

- **Linux** — сервис использует nftables, на других ОС не собирается/не работает.
- Права на управление nftables (`CAP_NET_ADMIN`, обычно — запуск от root).
- Внешняя настройка (вне этого сервиса): маршрутизация `fake_cidr` в туннель,
  `net.ipv4.ip_forward=1`, при необходимости SNAT/masquerade на исходящем
  интерфейсе. Сам сервис программирует только DNAT-набор в nftables.

## Сборка

`make` собирает бинарь в `build/antizapret_go` (по умолчанию `GOOS=linux`,
`GOARCH=arm64`, `CGO_ENABLED=0`; версия проставляется через ldflags):

```sh
make
```

Под другую архитектуру — напрямую через `go build`:

```sh
GOOS=linux GOARCH=amd64 go build -o antizapret_go ./cmd/
```

## Запуск

```sh
# показать дефолтный конфиг
./antizapret_go -default-config > config.yaml

# запуск с конфигом (нужны права на nftables)
sudo ./antizapret_go -config config.yaml
```

Флаги: `-config <path>` — путь к конфигу; `-default-config` — напечатать дефолтный
конфиг и выйти; `-help` — справка. Без `-config` используется встроенный дефолт.

## Конфигурация

### `bindings` — слушатели DNS

| Поле       | Описание                                  |
|------------|-------------------------------------------|
| `address`  | адрес прослушивания (`127.0.0.1`, …)      |
| `port`     | порт (обычно `53`)                        |
| `protocol` | `udp` или `tcp`                           |

Bind на wildcard (`0.0.0.0`/`::`) логируется предупреждением — следите, чтобы не
получился open-resolver.

### `upstreams` — вышестоящие DNS

| Поле      | Описание                                                                 |
|-----------|--------------------------------------------------------------------------|
| `name`    | имя (для логов; по умолчанию — хост)                                      |
| `dsn`     | `udp://host:53`, `tcp://host:53` или `https://host/dns-query` (DoH)       |
| `timeout` | таймаут одной попытки к этому апстриму                                    |

Апстримы перебираются по кругу с фолбэком; общий бюджет запроса — `request_timeout`.

### `policy` — списки и их перезагрузка

- `reload_interval` — период автоматического ребилда роутера (также по `SIGHUP`).
- `matchers` — источники списков (см. ниже).

### `policy.matchers[]` — источник списка

| Поле         | Описание                                                                            |
|--------------|-------------------------------------------------------------------------------------|
| `name`       | имя источника (ключ кэша снимков)                                                    |
| `type`       | `remap` / `blackhole` / `passthrough`                                                |
| `source`     | `file:///path` или `http(s)://…`                                                     |
| `format`     | `plain` (домен на строку, `#`-комментарии) или `regexp` (escape-hatch)               |
| `subdomains` | `true` ⇒ домен и поддомены (`*.domain`), `false` ⇒ только точное совпадение; деф. `true` |
| `regexp`     | для `format: regexp` — `{ from, to }`: строки, матчащие `from`, преобразуются в `to` |
| `filter`     | `{ exclude: [regexp, …] }` — отбросить записи, чьи (канонические) домены матчат любой |

Если домен встречается в нескольких источниках, **выигрывает последний** в списке
`matchers`.

### Прочее

| Поле               | Описание                                                                      |
|--------------------|-------------------------------------------------------------------------------|
| `fake_cidr`        | пул fake-IP для `remap` (напр. `10.30.0.0/15`); должен заворачиваться в туннель |
| `cache.capacity`   | максимум записей в DNS-кэше                                                    |
| `cache.ttl`        | дефолтный TTL кэша, если у ответа нет своего                                   |
| `nft.set`          | имя nftables-set                                                               |
| `nft.chain`        | имя nftables-chain (NAT, prerouting)                                           |
| `nft.ttl`          | время жизни маппинга fake→real (после чего IP переиспользуется)                |
| `request_timeout`  | общий бюджет на резолвинг одного запроса (покрывает фолбэк по апстримам)       |
| `logging_severity` | `debug` / `info` / `warn` / `error`                                            |
| `state_path`       | путь к bbolt-файлу (persistent кэш списков + быстрый старт)                    |

## Технический долг

- **Наблюдаемость.** Нет метрик и health/ready-эндпоинта. Желательно: qps,
  cache hit-rate, заполненность fake-пула (ранний сигнал об исчерпании → SERVFAIL),
  ошибки/латентность апстримов, возраст и статус последнего ребилда роутера, размер
  radix. Отложено: ЦА — частное использование, развёрнутого Prometheus обычно нет;
  стек под вопросом (Prometheus vs expvar).
- **Тесты.** Низкое покрытие. Нужны юнит-тесты (TTL-логика кэша, конвейер роутера
  parser/filter/normalize/last-wins, round-trip bbolt-store, конкурентность
  IPMapper) и интеграционный тест направления nft DNAT на Linux.
- **Контеншн `SafeTTLMap`.** `Get` обновляет accessTime под полным мьютексом на
  каждом чтении; `Clean` сканирует всю map под локом. Перед оптимизацией снять
  профиль/бенч.
- **Роутер.** Источники тянутся последовательно (можно распараллелить); нет
  ETag/conditional GET (каждый refresh качает список целиком); `bufio.Scanner` с
  лимитом строки 64KB — гигантская строка уронит парсинг источника.
