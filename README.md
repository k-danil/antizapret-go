# antizapret-go

Проект вдохновлён [GubernievS/AntiZapret-VPN](https://github.com/GubernievS/AntiZapret-VPN)
и не претендует на авторство идеи или применённых в нём решений. Цель —
минимизация зависимостей и простота развёртывания новых инсталляций при
сохранении достаточной гибкости. Поднятие VPN, firewall и маршрутизация остаются
на стороне оператора; antizapret-go отвечает только за проксирование (подмену DNS).

DNS-прокси для **селективной маршрутизации по доменам**: через VPN-туннель
направляется трафик только к доменам из заданных списков, остальное идёт напрямую
(split-tunnel по доменам, а не по IP).

Сервис работает как DNS-резолвер для клиента: резолвит имя, классифицирует домен
по спискам и для доменов из remap-списка отдаёт клиенту **fake-IP** из приватного
пула вместо реального адреса, попутно программируя в файрволе DNAT `fake → real`.
Пул fake-IP целиком заворачивается в туннель маршрутизацией, поэтому в туннель
попадает только нужный трафик.

## Как это работает

```
DNS-запрос клиента
      │
      ▼
   [ cache ] ──hit──► ответ (с пересчётом TTL)
      │ miss
      ▼
 [ resolver ] ── round-robin апстримы с фолбэком ──► кэшируем ответ
      │
      ▼
 [ router ] ── классификация домена по спискам (longest-prefix)
      │
      ├─ passthrough → реальный IP как есть (трафик напрямую)
      ├─ blackhole   → A заменяется на 127.6.6.6 (домен отбрасывается, sinkhole)
      └─ remap       → A заменяется на fake-IP из fake_cidr,
                       в файрволе прописывается DNAT fake → real
```

1. Клиент использует сервис как DNS-резолвер.
2. Кэш (ключ = `имя|тип|класс`); на miss — резолвинг через апстримы (round-robin
   со стартовым смещением и фолбэком на следующий при сбое).
3. Роутер определяет действие для **запрошенного** домена.
4. Для `remap` берётся fake-IP из пула, программируется DNAT в prerouting; клиент
   получает fake-IP, коннект к нему заворачивается в туннель и на этой машине
   разворачивается обратно в реальный адрес.
5. Для `remap`/`blackhole` ответ принудительно сводится к подменяемой `A`-записи:
   `AAAA` вырезается (чтобы реальный IPv6 не утёк мимо туннеля), а `HTTPS`/`SVCB`
   глушатся пустым NODATA — их подсказки (`ipv4hint`, ECH) увели бы клиента мимо
   подмены `A`. В обоих случаях клиент падает на `A`-запрос.
6. Маппинги fake→real живут ограниченное время (`firewall.ttl`) и переиспользуются.
   Состояние DNAT хранится в ядре (nftables-set / iptables-цепочка) и **переживает
   рестарт процесса**: на старте сервис усыновляет уже существующие правила, а не
   обнуляет их, поэтому клиенты с закэшированным fake-IP не теряют связь при
   перезапуске/апгрейде (после полного reboot — чистый старт, если оператор не
   восстанавливает ruleset). Списки перечитываются периодически и по `SIGHUP`;
   снимки списков персистятся per-source (run-файлы + скомпилированный FST) — для
   быстрого старта и устойчивости к временной недоступности источников
   (last-known-good); неизменившиеся источники не перекачиваются.

## Требования

- **Linux — для работы.** Реальные DNAT-бэкенды (nftables/iptables) есть только под
  Linux. Сам проект собирается и тестируется на любой ОС (вне Linux firewall-бэкенд —
  `noop`, см. ниже) — удобно для разработки.
- Права на управление файрволом (обычно — запуск от root; для `iptables` см. ниже про contrib-юнит).
- Внешняя настройка (вне этого сервиса): маршрутизация `fake_cidr` в туннель,
  `net.ipv4.ip_forward=1`, при необходимости SNAT/masquerade на исходящем
  интерфейсе. Сам сервис программирует только DNAT в выбранном бэкенде.

## Сборка

`make` собирает бинарь в `build/antizapret_go` под **текущую платформу**
(`CGO_ENABLED=0`; версия — через ldflags). Кросс-сборка — через `GOOS`/`GOARCH`:

```sh
make                            # под хост
make GOOS=linux GOARCH=amd64    # под сервер
```

Деплойный `.deb` — `make deb` (всегда Linux; арка — `DEB_ARCH`, по умолчанию `amd64`;
нужен [`nfpm`](https://nfpm.goreleaser.com)):

```sh
make deb                  # → build/antizapret-go_<version>_amd64.deb
make deb DEB_ARCH=arm64
```

## Запуск

```sh
# показать дефолтный конфиг
./antizapret_go -default-config > config.yaml

# запуск с конфигом (нужны права на nftables)
sudo ./antizapret_go -config config.yaml
```

Флаги: `-config <path>` — путь к конфигу; `-default-config` — напечатать дефолтный
конфиг и выйти; `-help` — справка. Без `-config` используется встроенный дефолт.

## Конфигурация

### `bindings` — слушатели DNS

| Поле       | Описание                             |
|------------|--------------------------------------|
| `address`  | адрес прослушивания (`127.0.0.1`, …) |
| `port`     | порт (обычно `53`)                   |
| `protocol` | `udp` или `tcp`                      |

Bind на wildcard (`0.0.0.0`/`::`) логируется предупреждением — следите, чтобы не
получился open-resolver.

### `upstreams` — вышестоящие DNS

| Поле      | Описание                                                            |
|-----------|---------------------------------------------------------------------|
| `name`    | имя (для логов; по умолчанию — хост)                                |
| `dsn`     | `udp://host:53`, `tcp://host:53` или `https://host/dns-query` (DoH) |
| `timeout` | таймаут одной попытки к этому апстриму                              |

Апстримы перебираются по кругу с фолбэком; общий бюджет запроса — `request_timeout`.

### `policy` — списки и их перезагрузка

- `reload_interval` — период автоматического ребилда роутера (также по `SIGHUP`).
- `rebuild_timeout` — таймаут одного ребилда (бюджет на загрузку всех источников).
  На холодном старте (кэша списков ещё нет) сервис ждёт первый ребилд не дольше
  этого времени, затем начинает отвечать на запросы.
- `matchers` — источники списков (см. ниже).

### `policy.matchers[]` — источник списка

| Поле         | Описание                                                                                 |
|--------------|------------------------------------------------------------------------------------------|
| `name`       | имя источника (ключ кэша снимков)                                                        |
| `type`       | `remap` / `blackhole` / `passthrough`                                                    |
| `source`     | `file:///path` или `http(s)://…`                                                         |
| `format`     | `plain` (домен на строку, `#`-комментарии) или `regexp` (escape-hatch)                   |
| `subdomains` | `true` ⇒ домен и поддомены (`*.domain`), `false` ⇒ только точное совпадение; деф. `true` |
| `prune`      | `true` ⇒ записи источника обрезают все более специфичные ветки под собой (см. ниже)      |
| `regexp`     | для `format: regexp` — `{ from, to }`: строки, матчащие `from`, преобразуются в `to`     |
| `filter`     | `{ exclude: [regexp, …] }` — отбросить записи, чьи (канонические) домены матчат любой    |

**Разрешение совпадений.** Действие домена определяет **самая специфичная** запись
(longest-prefix): `www.example.com` из одного источника победит `example.com` из
другого независимо от их порядка. Порядок (last-wins) важен только для **полностью
совпадающего** ключа.

**`prune`** даёт оператору вайлдкард-оверрайд поверх чужих списков. Запись prune-источника
обрезает все более специфичные ветки под своим префиксом на момент обработки: если
community-лист добавил `www.example.com remap`, а ваш prune-`passthrough` источник —
`example.com`, то весь `*.example.com` пойдёт напрямую, перекрыв специфичную запись.
Так как прунинг точечный во времени, prune-источник должен идти **после**
перекрываемых списков (обычно — в конце). Это per-source флаг: чтобы в одном наборе
смешать вайлдкард-оверрайды и специфичные исключения, разнесите их по нескольким
упорядоченным источникам.

### Прочее

| Поле               | Описание                                                                                           |
|--------------------|----------------------------------------------------------------------------------------------------|
| `fake_cidr`        | пул fake-IP для `remap` (напр. `10.30.0.0/15`); должен заворачиваться в туннель                    |
| `cache.capacity`   | максимум записей в DNS-кэше                                                                        |
| `cache.ttl`        | дефолтный TTL кэша, если у ответа нет своего                                                       |
| `firewall.backend` | `nft` (по умолчанию), `iptables` или `noop` — чем программировать DNAT (см. ниже)                  |
| `firewall.set`     | имя nftables-set (только для `nft`)                                                                |
| `firewall.chain`   | имя цепочки DNAT (NAT/prerouting) — для обоих бэкендов                                             |
| `firewall.ttl`     | время жизни маппинга fake→real (после чего IP переиспользуется)                                    |
| `request_timeout`  | общий бюджет на резолвинг одного запроса (покрывает фолбэк по апстримам)                           |
| `processes`        | DNS-слушателей на каждый binding (SO_REUSEPORT, параллельный приём); по умолчанию — число ядер CPU |
| `logging_severity` | `debug` / `info` / `warn` / `error`                                                                |
| `state_path`       | директория состояния: per-source кэш списков + скомпилированный FST для быстрого старта             |
| `metrics.address`  | адрес admin-HTTP (`/metrics`, `/healthz`, `/readyz`); пусто = выключено; реком. localhost          |

### Бэкенды DNAT (`firewall.backend`)

- **`nft`** (по умолчанию) — nftables через netlink; маппинг в set-map (хеш-поиск).
  Предпочтителен: быстрее и дешевле при создании маппингов.
- **`iptables`** — для хостов без nftables-netlink, legacy-систем и совместимости
  с инсталляциями оригинала. Маппинг — цепочка DNAT-правил (по правилу на адрес):
  на больших объёмах и при всплесках новых доменов заметно медленнее `nft`. Требует
  таблицу `nat` и прав на iptables. При запуске через contrib-юнит systemd
  раскомментируйте в нём iptables-блок (`CAP_NET_RAW` + запись в `/run` для
  `xtables.lock`) — иначе операции с правилами падают из-за sandbox.
- **`noop`** — ничего не программирует: DNAT не создаётся. Для разработки/тестов и
  запуска вне Linux (реальные бэкенды — только под Linux); выбирается на любой ОС.
  С ним `remap` отдаёт клиенту fake-IP, но DNAT `fake → real` не пишется.

`nft`/`iptables` **переживают рестарт процесса**: состояние DNAT читается из ядра и
усыновляется на старте — активные маппинги `fake→real` не теряются.

## Производительность

Порядки величины (не гарантии — зависят от железа, сети и размера списков).
Главное: **CPU-работа на запрос ничтожна на фоне сети и firewall-I/O** — они и
задают латентность.

### Время ответа

- **Попадание в кэш** — единицы микросекунд (классификация + сборка ответа).
- **Промах кэша** — упирается в сетевой round-trip к апстриму: единицы–десятки мс
  (рекурсор), до сотен мс (DoH). Доминирует над всем остальным.
- **Новый remap-маппинг** (первое обращение к домену) — плюс запись правила в
  файрвол: `nft` — десятки микросекунд, `iptables` — единицы миллисекунд; повторные
  обращения к тому же real-IP правило не пишут.

Одинаковые одновременные промахи коалесцируются: в апстрим уходит один запрос на
имя, остальные ждут результат.

### Ресурсы

Память замерена на реальных RU-списках (удерживаемая Go-куча после GC, с учётом
округления аллокатора). Ниже — удельные значения и якоря.

- **Списки (FST)** — компактный конечный автомат: общие префиксы/суффиксы доменов
  сжимаются, поэтому объём **сублинеен** по числу записей. Якорь: **~1.5 млн доменов
  → ≈8 МиБ**. Грузится из файла в Go-кучу.
- **DNS-кэш** — **≈0.6 КБ на запись** с одной A-записью (+~56 Б за каждую
  дополнительную A в ответе) × `cache.capacity`. При дефолтных 20000 — **≈11 МиБ**.
- **Маппинги `fake→real`** — **≈40 Б на активный маппинг** (таблица + пул). 100k
  активных — **≈4 МиБ**. Пул не материализует `fake_cidr` (даже /8): держит курсор и
  список освобождённых адресов. Потолок числа маппингов — размер `fake_cidr`
  (при `/15` ≈ 131k).
- **Состояние на диске** (вне Go-кучи): per-source run-файлы (≈ объём отфильтрованных
  списков) и скомпилированный `matcher.fst` (≈8 МиБ); читаются транзиентно.
- **Перезагрузка списков — инкрементальная.** Неизменившиеся источники не
  перекачиваются и не перепарсиваются (условный fetch по ETag/mtime). При пересборке
  merge стримит run-файлы с диска: в RAM держится один источник на парсинге плюс буфер
  сборки FST, поэтому пик — десятки МиБ.
- Ядерный set/цепочка (nftables/iptables) живут в памяти **ядра** отдельно от Go-кучи.

**CPU** — суб-микросекундная работа на запрос; потолок задаёт сеть/файрвол, не CPU.

## Наблюдаемость

Опционально (по умолчанию выключено): задайте `metrics.address` — поднимется
admin-HTTP с эндпоинтами:

- `/metrics` — метрики в формате Prometheus (плюс стандартные `go_*` / `process_*`);
- `/healthz` — liveness (200, пока процесс жив);
- `/readyz` — readiness (200, когда загружен матчер списков; на холодном старте до
  первого ребилда — 503);
- `/version` — версия сборки.

Эндпоинты без аутентификации — держите адрес на localhost или закрывайте файрволом.

Что полезно мониторить (префикс метрик — `antizapret_`):

- `mapper_active_mappings` / `mapper_pool_capacity` — утилизация пула fake-IP; алерт на
  приближение к ёмкости упреждает `SERVFAIL` из-за исчерпания пула (см. ниже).
- `upstream_queries_total{upstream,result}` + `upstream_query_duration_seconds` —
  здоровье и латентность апстримов, эффективность round-robin-фолбэка.
- `router_rebuilds_total{result}` + `router_rebuild_duration_seconds` — свежесть и
  состояние источников списков.
- `dns_responses_total{rcode,action}` + `dns_request_duration_seconds{served}` —
  распределение ответов (SERVFAIL-rate), латентность и hit-ratio кэша (через лейбл
  `served`: cache vs upstream).
- `dns_cache_size` — наполнение кэша, тюнинг `cache.capacity`.

## Известные ограничения

- **Только IPv4.** `remap`/`blackhole` работают по IPv4: для таких доменов `AAAA`
  вырезается, а `HTTPS`/`SVCB` глушатся (NODATA), чтобы клиент шёл через подменённую
  `A`. Домен, доступный только по IPv6, работать через прокси не будет.
- **Исчерпание пула.** Если свободные адреса `fake_cidr` закончились, новые
  remap-домены получают `SERVFAIL`, пока адреса не высвободятся по `firewall.ttl`.
  Запас регулируется размером `fake_cidr`.
- **DNS-кэш эфемерен.** Маппинги `fake→real` переживают рестарт (усыновляются из
  ядра), но кэш DNS-ответов — нет: после рестарта он наполняется заново.
